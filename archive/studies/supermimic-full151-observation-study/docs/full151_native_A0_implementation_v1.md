# Full151 native A0 implementation

This stage implements the one-world native A0 path for `rough_observation_reference_full151_v1` and `legacy_H123_full151_SCP8_knownrough_v1`. The CPU contract is complete; actual environment construction, native reset physics, device clock and the 3-second episode remain untested at this stage. The parent reference remains geometrically and physically unqualified.

`full151_native.native.run_native(config, bundle, output, emit)` accepts only method `A0`, role `native_a0`, one world, a separately authorized configuration and the new full151 bundle. It constructs a Manager environment and native PenSimReader; it does not construct an Actor, Runner or optimizer, load an old checkpoint, train, or provide an A2 target fallback.

The composition is outer `full151_runtime` and inner `full151_controller`. The nominal model is preserved, the eight actual context fields are copied with readbacks before and after `set_const_0(restore=True)`, and the explicit first reset uses the bundle's analytic velocity authority. NativeReader finite-difference velocity remains a separate ABI diagnostic. Startup records full qpos, qvel, control and mocap readbacks; object world linear velocity and native body angular velocity are distinct.

The probe executes 150 zero-residual actions, each through the original Manager step with four 5-ms integration steps and one original postinterval forward. It samples 601 states and 600 solver records, retains all 150 native reward snapshots with state58, selfcollision15, torque, terms and PEN memory, and allows no action `u150`. The reference-end timeout occurs after phase149 with terminal observation150. Quality failure never shortens the planned episode; instability, an unexpected terminal, clock/ABI error or deadline remains an engineering failure with partial output.

Each returned episode step is counted independently of its subsequent sample. Separate API attempt/return counters distinguish a throwing API from a throwing readback. Complete coverage requires 600/600 step attempts/returns and 150/150 forward attempts/returns. The public physical-step counter denotes returned step APIs, and sampled solver rows are separate. Constructor, setup, reset and graph work are explicitly `UNKNOWN_NOT_WHOLEPROCESS_OBSERVED`; these episode counts are not whole-process kernel counts.

The thirteen quality gates retain the original position, directed local-x shaft, joint margin, penetration, target-rate, signed force/load and drop criteria. Primary tracking uses 151 control knots; the full 601-state tracking extrema are also reported. The new clock contract requires both bit-exact sequential float32 additions and the original full151 50-us canonical-time drift bound. Its CPU recurrence ends at 3.00002121925354 s (21.21925354 us drift); the old prefix 2-us criterion is diagnostic only. No simulator time is rewritten.

The hash-bound capacity observer reads before the first reset and once finally, preserving a constructor-stage read and any failure before the outer context yields. It never clears sticky flags. Contact force and penetration samples describe the just-completed preintegration solver, whereas qpos/qvel are postintegration. The native reward snapshot remains the selfcollision15 authority before the original Manager forward. No extra forward or step is used to acquire diagnostics.

`scripts/check_full151_a0_source_cpu_v1.py` ran once with `CUDA_VISIBLE_DEVICES=-1`: 44/44 checks passed. It used the actual native factory only to build a configuration, passive loading of the already-produced bundle and static MJB, synthetic grading/capacity data, and the candidate's extracted wrappers with no-device callables. Actual Env construction and all thirteen denied native kinematic, collision, force-query and physics API counters were zero. The fixture's transitive framework imports are recorded; CUDA remained unavailable and uninitialized. Pre-execution source snapshots and the report are in `outputs/full151_A0_CPU_contract_v1`. This proof establishes the stated CPU contracts, not physical feasibility, contact quality or training readiness.

The original full151 input, failed SCP results, rough104 paths and shared catalog are unchanged. A0 results must remain a new cohort; no prefix physics or old checkpoint qualification is inherited. A1L training and full151 contact-intent objectives require separate implementation, evidence and authorization.

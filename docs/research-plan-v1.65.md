# Research plan v1.65 — repair the exported CPU pen collision tree

The device and CPU host have different inertial axes for the pen. On a fresh guarded W1 runtime, the native host BODY quaternion was [0.5, 0.5, 0.5, 0.5], the live GPU quaternion was [1, 0, 0, 0], and the previous CPU physics exporter copied the GPU quaternion into an independent model but kept the host BVH boxes. In the resulting inertia frame the long side of the tree lies along z while the endpoints lie on x. The old root under-encloses the physical pen by 116 mm. Repeating mj_setConst alone did not refit it. This is a reproducible export-path defect specific to this compiled asset, not a claim about all CPU or GPU collision implementations. See [host before/after](../runs/pen_before_export_v1/report.json).

For future CPU audits use the [verified export function](../src/supermimic_research/runtime/pen_cpu_model_export.py). It retains the old parameter snapshot and emits a distinct repaired MJB and receipt. The [refit](../src/supermimic_research/mechanics/pen_body_bvh.py) changes exactly the five bounding-box rows on a copy. Analytic cylinder and box extrema confirm each node encloses its descendants. Original mesh, geom, actuator, mass, inertia, solver and stored checkpoints remain traceable. A newly constructed W1 model was successfully exported and reloaded.

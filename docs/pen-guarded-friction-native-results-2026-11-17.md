## 从失败资格到具体修正

前三版资格失败保持原样。为定位回退差异，新探针对全部139,160条原始摩擦输入比较原版、恒等包装、旧稳定包装与有条件包装，并保存生成 CUDA/PTX。实际 GPU 舍入指令在全部2,016条跨区间输入上得到：

- 原单步长回退逐字节匹配 `fma(-prefix0,term0,rounded_cost1)`。
- 原三步长回退逐字节匹配 `fma(prefix1,term1,-rounded_cost0)`。
- 旧无条件稳定包装回退匹配 `rounded_cost1-rounded_cost0`，两次绝对代价均先舍入。
- 恒等包装保持原输出；先检查可处理区间、否则直接调用原函数的包装，同时保留原导数、Hessian 和回退字节。

这明确区分了所测输入上的舍入结果，支持修正包装拓扑；没有将保存的 PTX 当作最终驱动 SASS 或唯一编译器因果链的证明。没有硬编码这些输入或拟合门槛。生产包装在摩擦同区间使用独立 FP64 代价中间量，返回 FP32；其余情况通过未包装的原函数返回。三步长仅在至少一点可处理时进入稳定分支，各点仍独立回退。原 `_solve_done` OR 条件、solver/line-search50、非摩擦函数、物理参数与动作保持原定义。

V4 工厂复用上述已测分支 AST，并使用独立模块缓存及所有者名称。实际 GPU 算术资格 **22/22**：同 alpha、三个不同 alpha、分开原版/候选辅助内核均检查导数/Hessian及回退字节；实际完整工厂以block32编译。不同 alpha 的检查覆盖同一三点调用内混合可处理/回退的情况。保存算术独立复核 **31/31**。完整 CPU 套件638项，637项通过、1项GPU测试按设计跳过；该GPU分支单独执行通过，之后正式资格重新覆盖生产辅助函数；另1项调度检查通过。

最初舍入探针 V1 因使用不存在的 `wp.vec` 在导入阶段失败。我在独立 V2 中改为 `wp.types.vector` 并先执行 CPU 检查；原源码、日志和未执行意图保留。该失败发生在 `wp.init`/任何 `wp.launch` 之前，新增4/4关闭核对，实际探针调用0，没有重启旧输出。CPU 开发过程中原生 C++ cast 的宏冲突也在 V2 冻结前修正。

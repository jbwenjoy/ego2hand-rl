# 物理状态保存恢复：字节复制通过，多环境轨迹仍不重复

本轮完成受控转笔的portable状态实现和实际新进程对照。单环境不间断恢复
通过1149/1149；32环境754/1149，不能宣称完整物理续跑合格。32环境同进程
也失败，表明差异不限于新进程加载。未进行实际Actor更新、WM拟合或真实ego
实验；完整研究目标仍进行中，原任务及受力/梯度失败未改变。

## 实现与范围

实际fresh-reset清单识别404个原生模型数组、169个动力学数组、241个Torch
张量、20个额外数组、811个标量、203个不透明资源和177个别名。原始清单
保存在`runs/pen_native_closure_inventory_v1`，不是完整恢复证明。

`controlled_pen_native_portable_state:2`保存全部原生model/Data，包括实际
warmstart、控制、mocap、活动/非活动约束与接触scratch；保留NaN payload字节。
受控Python闭包另存221个张量、reset-mask数组及784个标量/配置字段，含
实体控制目标、动作EMA/掩码、命令阶段/采样计时、episode/pending/仿真计数。
数组合计795字段。模型/数组key、shape、dtype、标量布局及别名逐项检查，
复制到新环境已有分配，不替换CUDA图的指针；不可变tuple/frozen字段先验值
相同才接受。RNG覆盖Python、NumPy、Torch CPU及所有CUDA设备。

WarpBridge仅持有原生数组视图/包装缓存与流资源，由新环境重建，底层数组
单独复制。仅在这个无观测噪声/无历史的接口中，extras、env.obs_buf和
ObservationManager._obs_buffer作为下一步重算的输出缓存排除。编译spec、
host setup data、设备/CUDA图是明确列出的资源类，以host模型二进制摘要、
静态布局和实际源码pin核对重建兼容性；不将未知可变对象静默跳过。未证明
这种排除规则适用于带延迟/DR/扰动或其他任务。网络/优化器还不在此payload内。

首批实现修复了三个实际加载问题，全部失败目录/源码保留：环境四个边界
字段在第一次step才创建；属性插入顺序不能代替稳定路径/别名契约；frozen
配置应在复制前验证，而不能重新赋值。v1/v2在任何物理复制前拒绝布局，v3
在标量写入阶段失败，无后续积分；修复后使用新生产者目录重新生成检查点，
没有绕过源码pin去修改旧检查点。

## 不间断边界的主要对照

新协议`configs/pen_native_resume_v2.toml`：8个控制步前缀、8个续段，50Hz，
dt2.5ms；不在保存边界注入重置。正常terminal的显式重置仍保留并比较。
对照按已有`pen_gpu_step_audit_v1.toml`的状态/控制/受力门槛，没有放宽。

|对照|逐项检查|795数组即刻复制|续段最大物体位置差|最大完整角度差|结果|
|---|---:|---|---:|---:|---|
|新进程，1环境|1149/1149|全部逐字节相同|0|0|本批短续段通过|
|新进程，32环境|754/1149|全部逐字节相同|1.124mm|4.116°|不合格|
|同进程，1环境|1148/1148|全部逐字节相同|0|约1.10e-5°|本批门槛通过，非逐位轨迹|
|同进程，32环境|756/1148|全部逐字节相同|1.042mm|5.612°|不合格|

新进程两组四类RNG的下一组取值均一致；跨进程和同进程的续段sample、
applied、EMA、PD target、phase、terminated/truncated掩码在本批全部一致。
因此不能将物理差异解释为策略动作不同。32环境原始接触的world归属、活动
EFC地址、有效前缀、容量、有限值及overflow检查全部通过。

接触行/约束分配顺序可不同，独立比较只在相同world、顺序geom对、condim
内以接触位置最小匹配，避免跨世界或行排序制造差异。新进程32环境第6个
零基子步先出现接触组变化，当时匹配局部力最大差仅3.35e-6N，未超过1e-4N；
WORLD合力第10子步才超标。其物体角速度、角度、位置分别在第30、33、52
子步超过原门槛。同进程32环境第6子步即有局部力1.11e-3N差异，随后角度/
位置也超标。不能把首个拓扑差异全部写成当时受力已超标。

新进程32环境最大匹配局部力差0.354N、WORLD合力差0.813N；同进程32也有
非零接触/状态分岔。它们与原生多世界接触的数值重复性问题相符，但尚未
定位具体核函数或排除所有隐藏依赖，不宣称原子归约、加载器或某种几何
算法已经被证明为唯一原因。单环境通过不推广到32环境/全7.36秒。

## 对后续学习工作的影响

精确存取通过与未来轨迹确定性是不同结论。上一方案把完整确定性回放设成
所有短训练的前置条件，现有同进程32对照说明这个条件会连原生引擎自身的
非重复性一起阻断。按方案v0.98将两项分开：继续定位接触分岔，保留未通过
的物理恢复/受力/WM梯度资格；独立PPO基线仅在输入/动作/终止/RNG/字节存取/
无辅助/容量等明确契约通过后推进，不把短训练当作SuperMimic或CHORD验收。
这不是通过放宽旧门槛取得成功，旧物理连续性结论仍为失败。

下一步实现terminal-next-value采集、网络/优化器/归一化与native payload的
完整训练检查点，以及声明预算的实际短训练；同时针对32环境首个分岔保存
完整子步源快照。本轮没有新的训练策略视频、任务成功、GPU加速或ego结论。
大检查点、接触轨迹和旧失败保留在`runs/`；精确入口与历史源码映射见
`provenance/pen_portable_state_results/ledger.json`。

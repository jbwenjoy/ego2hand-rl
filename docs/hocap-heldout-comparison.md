# 三名留出参与者的后续比较

主评测使用预留的参与者 2。参与者 5 和 6 各提供一条补充动作。分组先按源数据签名封存，三条动作之间不传递权重、回放或适配结果。开发集全部训练段和评测记录关闭之后，按预先指定的最后一段固定预算端点选择共享 FlashSAC 和共享世界模型各自的策略。策略的开发分数不参与选择。[比较规则](../configs/hocap_heldout_comparison_v1.json) · [签名分组](../runs/hocap_supplementary_reservation_v1/split_manifest.json)

WSL 中的驱动使用 FlashCHORD Python。按已确认的研究目标，开发训练结束并冻结最终检查点后，登记主比较与动力学迁移补充组，再解封三条源参考。评估者先审阅源图像并记录可见性，再开始策略评分。各阶段可重新执行，已完成的作业复核哈希后复用，失败的命令另起目录并计费。[比较驱动](../tools/run_wuji_heldout.py) · [共享动力学迁移补充组](hocap-heldout-dynamics-transfer.md)

| 命令 | 输入与产物 |
| --- | --- |
| `freeze-final` | 传入 `--repo --tranche --out --bulk --upstream --hand-python`。其中 `--out` 使用可由 Windows 解析的共享磁盘路径，`--bulk` 可在 WSL 文件系统中存储较大的检查点。确认全部开发轮次完成、源分组签名、预训练成本、最终检查点、规范初始化及代码哈希后写入选择摘要。 |
| `stage` | 传入 `--out --released-plan-sha256`。分别生成三个已释放源的运动学参考、资产和第一视角起止帧，按既定的两台相机和三个时刻补取可用深度。每名参与者会得到一份 `*_source_review.json`。研究者检查源端点图像，填入是否看见桌面支撑、实际审阅时间和计时依据，此时尚未载入策略评分。 |
| `freeze-stages` | 同样传入选择摘要哈希。为所有已分配动作登记源区间、适用性、完整性、静止对照与规则版本，产生第二个摘要哈希。无法评分的输入保留名额，两种共享方法和逐条方法均记录相同的输入缺失原因。 |
| `run` | 提供两个摘要哈希 `--released-plan-sha256 --registered-stages-sha256` 和 `--out`。先做独立 CPU/CUDA 物体校验，随后对所有可评分参与者做两组共享策略的零样本评测，再执行逐条冷启动与两组共享策略的逐条适配。 |
| `report` | 提供 `--out --released-plan-sha256`。生成逐人结果、方法成本、首次确认通过的评测点、主样本与补充样本的计数、未知耗时及独立扰动记录。 |

三个适配方法在每条目标轨迹上分到相同的真实环境步数，以开发计划确定的单参考课程总量作为上限，在四分之一、二分之一、四分之三和全预算时复测。逐条 CHORD 使用共同的第零步学习器。共享方法只迁移对应最终策略的 actor 与归一化统计，目标 critic、优化计数和目标回放从零开始，混合组的目标世界模型也从头拟合。最后预算与首次通过分别记录。模型在两个检查点之间首次达到要求的时刻仍未知。

每次评分同时保存历史严格门限、原始命令重放的数值差、两次全新物理场景的独立重复，以及采用冻结源阶段的判定。通过需要真实源全段、接触力校验和两次独立重复。零样本与最后预算的扰动在预先约定的干预时刻可触及时单列，未暴露、暴露不足和不适用均单独记录。[物理与扰动评估入口](hocap-heldout-evaluator.md) · [源阶段规则](hocap-heldout-source-stages.md)

费用从已有公开标注和网格开始，分列源准备、实际源审阅、刚体校验、零样本、目标训练、逐次评测和失败尝试。共同的源准备在每种独立部署方案中按每名目标收取一次。预训练与开发评测在该共享方法的多目标总成本中只收取一次。创建者最初采集视频及生成数据集标注的成本不在账内。协调器耗时另外列出；没有验证成功或关键耗时未知时，不给出每条成功成本。[成本聚合](../tools/heldout_wuji_cost.py)
